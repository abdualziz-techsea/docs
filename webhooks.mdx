title: "Webhooks"
description: "One endpoint, ten events, and how to verify that a delivery came from DropHub."
---

Webhooks tell your system that a shipment changed, without polling. Managing them requires `webhooks:manage`. A merchant has **one** webhook: the resource is `/api/v2/external/webhook`, singular.

## Register it

```bash
curl -X POST "$BASE_URL/api/v2/external/webhook" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://merchant.example/webhooks/drophub"}'
```

Omit `events` to subscribe to all ten. To narrow it, list the ones you act on:

```json
{ "url": "https://merchant.example/webhooks/drophub", "events": ["shipment.delivered", "shipment.failed", "shipment.cancelled"] }
```

The `201` response carries the endpoint and the signing secret (captured on the sandbox, secret redacted):

```json
{
  "webhook": {
    "endpointId": "01a19342-59c6-77a8-b377-495f3f1e7581",
    "url": "https://example.com/drophub-hooks",
    "status": "ACTIVE",
    "subscribedEventTypes": ["shipment.out_for_delivery", "shipment.created", "shipment.cancelled", "shipment.assigned", "shipment.no_driver_available", "shipment.failed", "shipment.updated", "shipment.delivered", "shipment.picked_up", "shipment.eta_updated"],
    "previousSecretValidUntil": null,
    "version": 0,
    "createdAt": "…",
    "updatedAt": "…"
  },
  "signingSecret": "<43 characters, base64url>"
}
```

`subscribedEventTypes` is a set; its order has no meaning.

<Warning>
  `signingSecret` is disclosed on creation and on rotation only. `GET /api/v2/external/webhook` never returns it. Store it immediately.
</Warning>

## Events

| Event | Sent when |
| --- | --- |
| `shipment.created` | The shipment was accepted |
| `shipment.assigned` | A driver accepted it |
| `shipment.picked_up` | Collected from the pickup point |
| `shipment.out_for_delivery` | On the way to the recipient |
| `shipment.delivered` | Delivered |
| `shipment.failed` | Delivery did not succeed (`data.reasonCode`) |
| `shipment.cancelled` | Cancelled (`data.reasonCode`) |
| `shipment.no_driver_available` | The driver search ended without a driver |
| `shipment.updated` | Destination, recipient, or pickup window changed; the lifecycle state is unchanged |
| `shipment.eta_updated` | A driver leg got its first estimate, or the estimate moved by at least 5 minutes |

An endpoint created before the newer events existed keeps its own list; add them with `PATCH`.

## The delivery

Captured on the sandbox:

```json
{
  "id": "evt_01a192823cd876bfae62da06705d1ed6",
  "data": {
    "eta": { "target": "PICKUP", "estimatedArrivalAt": "2026-10-31T15:10:35.937375Z" },
    "reference": "APIREF-1",
    "shipmentId": "01a19282-038d-7b17-9c8d-45209747ec1d",
    "lifecycleState": "ACCEPTED",
    "proofAvailable": false,
    "shipmentVersion": 2,
    "deliveryFeeAmount": 34.00,
    "merchantCompanyId": "01a19281-32ad-71f4-96e4-5d9caeb466a4",
    "deliveryFeeCurrency": "SAR"
  },
  "type": "shipment.eta_updated",
  "sequence": 2,
  "apiVersion": "2026-08-25",
  "occurredAt": "2026-10-31T15:09:30.937375Z"
}
```

Every event carries `shipmentId`, `reference`, `merchantCompanyId` (the store), `status`, `lifecycleState`, `shipmentVersion`, `deliveryFeeAmount`, `deliveryFeeCurrency`, and `proofAvailable`. `reasonCode` is added on `shipment.failed` and `shipment.cancelled`; `eta` on `shipment.eta_updated`. `sequence` equals `shipmentVersion`. Several events can share one value — `shipment.eta_updated` does not change the shipment's version — so deduplicate on `Webhook-Id`, not on `sequence`.

<Note>
  `status` is the same [status](/shipments#status) the shipment read returns. `lifecycleState` is DropHub's internal state name (for example `PENDING_APPROVAL`, `ACCEPTED`, `DELIVERY_FAILED`); it is kept for existing receivers — use `status`.
</Note>

Several stores may use one receiver URL; `data.merchantCompanyId` identifies the store and each store has its own signing secret.

## Verifying the signature

| Header | Contents |
| --- | --- |
| `Webhook-Id` | The event id (the envelope `id` is `evt_` + this UUID without dashes) — deduplicate on it |
| `Webhook-Timestamp` | Unix time in **seconds** of this attempt |
| `Webhook-Signature` | `v1=` + unpadded **base64url** HMAC-SHA256 |
| `Idempotency-Key` | Stable across retries of one event |
| `User-Agent` | `DropHub-Webhooks/2.0` |

The signed message is:

```text
{Webhook-Id}.{Webhook-Timestamp}.{raw body}
```

<Warning>
  The HMAC key is the **decoded** secret: base64url-decode the 43-character `signingSecret` to 32 bytes. Verify against the raw bytes you received, before any JSON parsing.
</Warning>

```python
import base64, hashlib, hmac

def verify(signing_secret: str, webhook_id: str, timestamp: str,
           raw_body: bytes, header: str) -> bool:
    key = base64.urlsafe_b64decode(signing_secret + "=" * (-len(signing_secret) % 4))
    message = webhook_id.encode() + b"." + timestamp.encode() + b"." + raw_body
    digest = hmac.new(key, message, hashlib.sha256).digest()
    expected = "v1=" + base64.urlsafe_b64encode(digest).decode().rstrip("=")
    return hmac.compare_digest(expected, header)
```

```javascript
import { createHmac, timingSafeEqual } from "node:crypto";

export function verify(signingSecret, webhookId, timestamp, rawBody, header) {
  const key = Buffer.from(signingSecret, "base64url");
  const message = Buffer.concat([Buffer.from(`${webhookId}.${timestamp}.`), rawBody]);
  const expected = "v1=" + createHmac("sha256", key).update(message).digest("base64url");
  const a = Buffer.from(expected), b = Buffer.from(header);
  return a.length === b.length && timingSafeEqual(a, b);
}
```

Reject deliveries whose `Webhook-Timestamp` is far from your clock.

## Responding and retries

Return a `2xx` quickly and process asynchronously. HTTP `408`, `425`, `429`, `5xx`, timeouts, and transport failures are retried with the same `Webhook-Id`, body, and `Idempotency-Key`, and a fresh timestamp and signature. The delay before attempt *n* is a random value up to 30 seconds × 2<sup>n−1</sup>, capped at 1 hour; `Retry-After` is honoured up to 1 hour. After 8 attempts the event is not retried again.

There is no replay or test-send API. After an outage, read the shipments you care about — the current status is authoritative.

## Changing it

`PATCH`, `DELETE`, and rotation require the endpoint's current version in `If-Match` (from `GET` or the last response's `ETag`). Missing → `428`; stale → `412`.

```bash
curl -X PATCH "$BASE_URL/api/v2/external/webhook" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "If-Match: \"1\"" \
  -H "Content-Type: application/json" \
  -d '{"status":"PAUSED"}'
```

`PATCH` accepts `url`, `status` (`ACTIVE` or `PAUSED`), and `events`. An unknown event name answers `422 UNSUPPORTED_EVENT_TYPE`.

<Note>
  After `DELETE /api/v2/external/webhook` you can register a new webhook; it gets a new signing secret. While a webhook exists, a second `POST` with a different body is refused with `409 IDEMPOTENCY_KEY_REUSED`.
</Note>

## Rotating the secret

```bash
curl -X POST "$BASE_URL/api/v2/external/webhook/secret-rotations" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "If-Match: \"2\""
```

Rotation returns a new `signingSecret` and sets `previousSecretValidUntil` 24 hours ahead. Every delivery sent after the rotation — including retries of earlier events — is signed with the **new** secret only, so switch your verifier to it as soon as you receive it. Keep accepting the old secret only for deliveries already in your queue.
