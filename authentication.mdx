## Your credentials

Copy your `client_id` and `client_secret` from the DropHub dashboard. They give full access to the External API for your store.

<Warning>
  The secret is shown once. Store it safely. If it is lost, revoke it in the dashboard and create a new one.
</Warning>

## Get a token

```bash
curl -X POST "$BASE_URL/api/v2/oauth/token" \
  -u "$CLIENT_ID:$CLIENT_SECRET" \
  -d grant_type=client_credentials
```

Form-body credentials also work:

```bash
curl -X POST "$BASE_URL/api/v2/oauth/token" \
  --data-urlencode grant_type=client_credentials \
  --data-urlencode client_id="$CLIENT_ID" \
  --data-urlencode client_secret="$CLIENT_SECRET"
```

The body must be `application/x-www-form-urlencoded`. The response:

```json
{
  "access_token": "<token>",
  "expires_in": 900,
  "token_type": "Bearer"
}
```

Send it on every `/api/v2/external` request as `Authorization: Bearer <access_token>`.

Each credential belongs to one store. A partner serving several stores uses one credential per store. A shipment that belongs to another store answers `404`.

## Token lifecycle

Read `expires_in` rather than assuming a duration. Cache the token and refresh a little before it expires. If a request fails with `401`, get a new token and retry once. Repeated `401`s after a fresh token mean the credential was revoked.

## Token endpoint errors

| Status | Body | Meaning |
| --- | --- | --- |
| `400` | `{"error":"invalid_request"}` | No credentials or a malformed form |
| `400` | `{"error":"unsupported_grant_type"}` | `grant_type` is not `client_credentials` |
| `401` | `{"error":"invalid_client"}` | Unknown, wrong, or revoked credential |
| `415` | problem details | The body was not form-encoded |
| `429` | `{"error":"rate_limited"}` | Too many token requests; wait for `Retry-After` |
