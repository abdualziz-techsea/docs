---
title: "Tracking"
description: "Your view of a shipment's progress, and the customer's."
---

There are two tracking views. Yours is authenticated and identifies the order. Your customer's is a link with no credentials and no identifiers in it.

## Your view

```bash
curl "$BASE_URL/v2/external/shipments/$SHIPMENT_ID/tracking" \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Requires `shipments:read`.

```json
{
  "id": "0198f7c0-7f51-7000-8000-000000000001",
  "reference": "ORDER-1042",
  "status": "OUT_FOR_DELIVERY",
  "driverLocation": {
    "latitude": 24.7601,
    "longitude": 46.7203,
    "accuracyMetres": 12,
    "recordedAt": "2026-08-27T08:41:12Z",
    "stale": false,
    "ageSeconds": 8
  },
  "locationStatus": "AVAILABLE",
  "recommendedRefreshSeconds": 15,
  "history": [
    { "status": "CREATED",          "at": "2026-08-27T06:00:00Z" },
    { "status": "ASSIGNED",         "at": "2026-08-27T06:04:31Z" },
    { "status": "PICKED_UP",        "at": "2026-08-27T07:52:00Z" },
    { "status": "OUT_FOR_DELIVERY", "at": "2026-08-27T08:10:44Z" }
  ]
}
```

`history` is the shipment's [public statuses](/shipments#status) in order, each with the instant it was reached.

## The customer's view

Every shipment gets a tracking URL at creation. You do not create, request, or revoke it — it comes back on the create response as `trackingUrl`, and it is the link to give your buyer.

```bash
curl "$BASE_URL/v2/public/tracking/jhJ4hVsHM7APbKpYKg3f7w4m2fC0ZLDm7KqTKi2B1zA"
```

No `Authorization` header. The 43-character code in the path is the credential, so the link is bearer-like: anyone holding it can see the shipment's progress.

```json
{
  "status": "OUT_FOR_DELIVERY",
  "driverLocation": { "latitude": 24.76, "longitude": 46.72, "recordedAt": "2026-08-27T08:41:12Z", "stale": false, "ageSeconds": 8 },
  "locationStatus": "AVAILABLE",
  "recommendedRefreshSeconds": 15,
  "history": [ { "status": "CREATED", "at": "2026-08-27T06:00:00Z" } ]
}
```

<Info>
  The public view is deliberately thinner: coarse driver position only, and no order reference, shipment id, merchant, recipient, pickup, or destination. Responses are `no-store` and rate limited.
</Info>

## Location status

`driverLocation` is `null` unless a position is genuinely available. `locationStatus` always says why:

| Status | Meaning |
| --- | --- |
| `NOT_ASSIGNED` | No driver is assigned yet |
| `WAITING_FOR_DRIVER_ACCEPTANCE` | Offered, not yet accepted |
| `LOCATION_UNAVAILABLE` | A driver is assigned but no position is available |
| `AVAILABLE` | A current position is available |
| `STALE` | A position is available but older than the freshness budget |
| `TERMINAL_NO_LIVE_LOCATION` | The shipment reached a terminal status |

When a position is present it carries `recordedAt`, `ageSeconds`, a `stale` flag, and — in your view only — an optional `accuracyMetres`.

<Warning>
  Never present a `STALE` position as the driver's current location. The `stale` flag and `ageSeconds` exist so your UI can say "last seen 4 minutes ago" rather than implying live movement.
</Warning>

## Polling

`recommendedRefreshSeconds` is between 5 and 60 and reflects what is actually knowable right now — a shipment waiting for a driver has nothing to report as often as one in motion.

<Tip>
  Honour `recommendedRefreshSeconds` instead of choosing your own interval. Polling faster does not produce fresher data. For state changes, [webhooks](/webhooks) are the right mechanism; tracking is for showing a live map.
</Tip>
