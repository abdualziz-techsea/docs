## Create

```bash
curl -X POST "$BASE_URL/api/v2/external/shipments" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
        "reference": "ORDER-1042",
        "pickup":      { "savedLocationCode": "SANDBOX_PICKUP" },
        "destination": { "latitude": 24.774265, "longitude": 46.738586 },
        "recipient":   { "name": "Noura", "mobile": "0551234567" }
      }'
```

| Field | Rule |
| --- | --- |
| `reference` | Required, up to 128 characters. Your order identifier and the default idempotency key. |
| `pickup` | Required. `savedLocationCode` (from [pickup locations](/availability#pickup-locations)), **or** `latitude` + `longitude` — never both. |
| `destination` | Required. `latitude` −90…90, `longitude` −180…180, at most 6 decimals. |
| `recipient.name` | Required, up to 120 characters. |
| `recipient.mobile` | Required Saudi mobile: `05XXXXXXXX`, `5XXXXXXXX`, or `+9665XXXXXXXX`. |
| `parcel` | Optional. `description` (≤ 160, default "Parcel"), `pieces` (1–100, default 1), `weightKg` (> 0, default 1). |
| `codAmount` | Optional, > 0, two decimals. Omit for prepaid. |
| `pickupWindow` | Optional `start` and `end` (UTC instants, `end` after `start`). Must fit the pickup location's hours. |
| `quoteId` | Optional. A [quote](/availability#quotes) for the same pickup and destination, unused and not expired. |

### The response

`201` with `Location` and `ETag` headers:

```json
{
  "id": "01a1933c-72ef-745d-af3d-eb836db7878c",
  "reference": "AT-1793471573-1",
  "status": "CREATED",
  "trackingUrl": "/track/<tracking-code>",
  "codAmount": null,
  "deliveryFeeAmount": 34.00,
  "deliveryFeeCurrency": "SAR",
  "eta": null,
  "proofAvailable": false,
  "proofType": null,
  "deliveredAt": null,
  "failureReasonCode": null,
  "cancellationReasonCode": null,
  "driver": null,
  "createdAt": "2026-10-31T18:32:54.767375Z",
  "version": 0
}
```

`deliveryFeeAmount` is the merchant delivery charge frozen on the shipment — the quoted price when you passed `quoteId`. `codAmount` is collected from the recipient and is separate.

### Quote refusals

| Status | `code` | Meaning |
| --- | --- | --- |
| `422` | `QUOTE_NOT_FOUND` | Unknown quote, or another merchant's |
| `422` | `QUOTE_EXPIRED` | Older than 15 minutes |
| `422` | `QUOTE_MISMATCH` | The quote was for a different pickup or destination point |
| `409` | `QUOTE_ALREADY_USED` | The quote already priced another shipment |

### Other refusals

A pickup window outside the pickup location's hours is refused with `422 PICKUP_OUTSIDE_OPERATING_HOURS`. Field validation failures are `422 VALIDATION_FAILED` with a `violations` list naming each field (including an invalid `Idempotency-Key`).

<Note>
  Creation accepts any destination; dispatch offers the shipment to the nearest available driver. [Serviceability](/availability#serviceability) tells you in advance whether a delivery company covers the destination.
</Note>

## Retries are already safe

| Situation | Result |
| --- | --- |
| Same reference (or `Idempotency-Key`), same request | `200` with the original shipment |
| Same reference (or key), different request | `409 IDEMPOTENCY_KEY_REUSED` |
| New reference | `201` — a new shipment |

See [Idempotency and ETags](/idempotency-and-etags).

## Read

```bash
curl "$BASE_URL/api/v2/external/shipments/$SHIPMENT_ID" \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Same shape as the create response, plus — while they apply — `eta` and `driver`:

```json
"eta": {
  "target": "PICKUP",
  "estimatedArrivalAt": "2026-10-31T18:35:00.819847Z",
  "estimatedMinutes": 2,
  "calculatedAt": "2026-10-31T18:33:11.819847Z",
  "distanceMetres": 1381
},
"driver": { "firstName": "Sandbox", "vehicleType": "CAR", "vehiclePlate": "SBX AB43" }
```

`eta.target` is `PICKUP` until pickup and `DELIVERY` after. `eta` is `null` before a driver accepts, right after pickup or a driver change until the next position arrives, and once the shipment has ended. `driver` shows only the first name, vehicle type, and plate — never a phone number.

## Change

```bash
curl -X PATCH "$BASE_URL/api/v2/external/shipments/$SHIPMENT_ID" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "If-Match: \"3\"" \
  -H "Content-Type: application/json" \
  -d '{ "recipient": { "name": "Noura A.", "mobile": "+966551112222" } }'
```

Send the shipment's current version in `If-Match`. Send only what changes:

| Part | Accepted |
| --- | --- |
| `destination` | Before pickup, and only when it prices the same as the frozen fee (any destination, as at creation) |
| `recipient` | Until the shipment ends |
| `pickupWindow` | Until a driver accepts, inside the pickup location's hours |

A successful change returns `200` with the shipment and a new `ETag`, and sends `shipment.updated`.

| Status | `code` | Meaning |
| --- | --- | --- |
| `428` | `PRECONDITION_REQUIRED` | `If-Match` missing |
| `412` | `PRECONDITION_FAILED` | Stale version — re-read first |
| `409` | `SHIPMENT_CHANGE_NOT_ALLOWED` | Too late in the lifecycle for that part |
| `409` | `SHIPMENT_PRICE_WOULD_CHANGE` | The new destination prices differently |
| `409` | `SHIPMENT_CHANGE_NOT_SUPPORTED` | The shipment came from Salla or Zid; change it there |
| `422` | `PICKUP_OUTSIDE_OPERATING_HOURS` | The window is outside pickup hours |
| `422` | `SHIPMENT_VALIDATION_FAILED` | Nothing to change (`{}`) |

## Status

| Status | Meaning |
| --- | --- |
| `CREATED` | Accepted; not yet assigned to a driver |
| `ASSIGNED` | A driver accepted it |
| `PICKED_UP` | Collected from the pickup point |
| `OUT_FOR_DELIVERY` | On the way to the recipient |
| `DELIVERED` | Terminal — delivered |
| `FAILED` | Terminal — delivery did not succeed; `failureReasonCode` says why |
| `NO_DRIVER_AVAILABLE` | The driver search ended without a driver; the shipment can still be cancelled |
| `CANCELLED` | Terminal — cancelled; `cancellationReasonCode` says why |

<Tip>
  Treat status as a value to read, not a sequence to assume. A shipment may skip what looks like a step.
</Tip>

## Proof and incidents

- `GET /api/v2/external/shipments/{id}/proof` (`shipments:read`) returns `pickedUpAt`, `pickupPhotoPath`, `deliveredAt`, `deliveryProofType` (`PHOTO`), `deliveryProofPath`, and `failureReasonCode`. The paths point to `/proof/pickup/content` and `/proof/delivery/content`, which return the image (`image/jpeg`, `Cache-Control: no-store`) for the same bearer token. A missing image answers `404`.
- `GET /api/v2/external/shipments/{id}/incidents` (`shipments:read`) returns an array of `{type, status, reasonCode, reportedAt, evidencePaths}`: `type` is `LOST`, `DAMAGED`, or `DELIVERY_FAILED`; `status` is `OPEN`, `RESOLVED`, or `FINAL`. Each evidence path returns an image for the same token.

<Note>
  There is no list or search endpoint. Store the shipment `id` against your order, and use [webhooks](/webhooks) for progress.
</Note>
