Every error is `application/problem+json` ([RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)) with DropHub extensions. Captured on the sandbox:

```json
{
  "detail": "The requested External MerchantStore operation could not be completed.",
  "instance": "/api/v2/external/shipments/01a1933c-72ef-745d-af3d-eb836db7878c",
  "status": 404,
  "title": "External MerchantStore operation rejected",
  "type": "https://api.drophub.example/problems/resource-not-found",
  "code": "RESOURCE_NOT_FOUND",
  "timestamp": "2026-10-31T18:33:04.503283Z",
  "correlationId": "d41a3e00-f1b1-4b0b-aa56-4ae897286d7c",
  "requestId": "2bb42235-b23c-4688-9675-1c6c9cd0732f"
}
```

<Note>
  `POST /api/v2/oauth/token` uses OAuth error bodies instead. See [Authentication](/authentication#token-endpoint-errors).
</Note>

## Fields

| Field | Purpose |
| --- | --- |
| `code` | **Stable machine code** — branch on this |
| `status` | HTTP status, repeated |
| `type` | URI identifying the problem kind; treat it as an opaque identifier |
| `title`, `detail` | Human-readable; may be reworded or localized |
| `instance` | The path that failed |
| `timestamp`, `correlationId`, `requestId` | Quote these when reporting a problem |
| `violations` | On validation failures: `[{field, code, message}]` |
| `nextAction` | On `SHIPMENT_RETURN_REQUIRED`: what to do instead |

## Validation failures

`422 VALIDATION_FAILED`. The response names each field:

```json
{ "code": "VALIDATION_FAILED", "violations": [ { "field": "destinationLatitude", "code": "OUT_OF_RANGE", "message": "This field is outside the allowed range." } ] }
```

Every field validation failure lists the offending fields in `violations`. A body with an unknown property or broken JSON is `400 MALFORMED_JSON`.

## Status codes

| Status | Meaning | Retry? |
| --- | --- | --- |
| `400` | Malformed JSON or unknown property | No — fix the request |
| `401` | Missing, malformed, or expired token | Once, with a fresh token |
| `403` | Valid token without the required scope | No |
| `404` | No such resource for this credential (including another merchant's) | No |
| `409` | Conflict with the resource's state, a used quote, or a reused idempotency key | No — re-read and reconcile |
| `412` | `If-Match` is stale | Re-read, then retry |
| `415` | Wrong `Content-Type` | No |
| `422` | Well-formed but invalid | No — fix the request |
| `428` | `If-Match` required but absent | Retry with the ETag |
| `429` | Rate limited | Yes — honour `Retry-After` |
| `503` | A DropHub dependency is unavailable | Yes — backoff with jitter |

## Common codes

| Code | Status | Where |
| --- | --- | --- |
| `QUOTE_NOT_FOUND`, `QUOTE_EXPIRED`, `QUOTE_MISMATCH` | 422 | Create shipment |
| `QUOTE_ALREADY_USED`, `IDEMPOTENCY_KEY_REUSED` | 409 | Create shipment |
| `SHIPMENT_RETURN_REQUIRED` | 409 | Cancel after pickup |
| `SHIPMENT_CHANGE_NOT_ALLOWED`, `SHIPMENT_PRICE_WOULD_CHANGE`, `SHIPMENT_CHANGE_NOT_SUPPORTED` | 409 | Change shipment |
| `PICKUP_OUTSIDE_OPERATING_HOURS` | 422 | Create or change shipment |
| `SHIPMENT_VALIDATION_FAILED` | 422 | An invalid order, or an empty change |
| `WEBHOOK_NOT_CONFIGURED` | 404 | Webhook reads and changes |
| `UNSUPPORTED_EVENT_TYPE` | 422 | Webhook `events` |
| `TRACKING_LINK_NOT_FOUND` | 404 | Public tracking |
| `SANDBOX_DRIVER_NOT_CARRYING_SHIPMENT`, `INSUFFICIENT_SCOPE`, `SANDBOX_ONLY` | 409, 403, 404 | Sandbox controls |
